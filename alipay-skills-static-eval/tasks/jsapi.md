# JSAPI 使用合规

检查 skill 目录下的 JS/TS 代码中是否使用了支付宝小程序 SKILL 不支持的 `my.*` API。

支持列表见 `references/supported-api.md`，其中「原子接口」「原子组件」「动态组件」三列标注了不同上下文下的支持情况。

## 输入

- skill 目录下的所有 JS/TS 文件
- skill 的 `mcp.json`
- 主 agent 传递的**组件清单**（`components`，每项含 `path` 与 `dynamic`，`dynamic` 为 `true` 即「实时动态组件」）
- 主 agent 传递的 alipay-skills-static-eval 根目录下的 `references/supported-api.md`

## 评测方法

### 1. 读取支持列表

读取 `references/supported-api.md`，按「原子接口」「原子组件」「动态组件」三列分别构建可用 API 集合。三列都标「不支持」的 API 不可在任何上下文中使用。

### 2. 确定每个文件的上下文

- **原子接口**：skill 目录下的 `index.js` 或 `index.ts` 是原子接口的入口。从该文件出发，沿 `import`/`require` 往下跟若干层，这些模块处于原子接口上下文。
- **原子组件 / 动态组件**：主 agent 传递的组件清单中 `components[].path`（相对 skill 目录）是各组件的入口。入口组件 `dynamic` 为 `true` 的，其整颗组件树（沿 `import`/`require` 引用到的所有模块）都处于**动态组件**上下文，用「动态组件」列比对；否则整颗组件树都处于**原子组件**上下文，用「原子组件」列比对。
- **重叠**：同一文件可能同时被多个上下文引用，不影响 — 分别在各自上下文标准下检查即可。

不需要构建完整模块依赖图，覆盖 skill 目录下的主要逻辑文件即可。

### 3. 扫描并比对

对每个文件，搜索所有 `my.*` 调用（包括 `my.xxx()`、解构后调用、链式调用），按该文件所处的上下文，用对应的 API 集合比对。

以下情况视为缺陷或潜在缺陷：

- API 在当前上下文中标为「不支持」或根本不在列表 → 缺陷
- 动态调用 `my[expr]()` 无法静态确定 → 潜在缺陷，建议动态评测

## 输出

```
## [skill 名称] — JSAPI 使用合规

### 问题
- [缺陷/潜在缺陷] [问题简述]
  - 位置：[文件:行号]
  - 原文：[代码片段]
  - 上下文：[原子接口 / 原子组件 / 动态组件]
  - 影响：[简述]
  - 建议：[改进方向]
```

无问题则一句话：「未发现 JSAPI 使用合规问题。」
