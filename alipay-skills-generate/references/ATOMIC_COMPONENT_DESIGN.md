# 小程序 Agent 卡片视觉设计规范

## §0 使用原则

1. 高频链路优先使用标准卡片模板，减少自由发挥带来的体验漂移。
2. KA 个性化场景可以使用通用卡片规范，但仍必须满足容器、间距、字号、按钮和信息层级底线。
3. 若本文与组件运行约束冲突，以 `COMPONENT_TEMPLATES.md` 和 `ACSS_SPEC.md` 的可生成约束为准。例如当前原子组件不生成 `input`、`textarea`、`picker` 标签，输入和选择通过半屏、上行消息或可点击展示行承接。
4. 标准模板只约束可复用的容器和视觉层级，不决定业务点击区域或控件形态；存在源交互映射时优先按源页面组织交互，并按总体用户动线突出主要下一动作。安全承接契约要求用户继续操作时必须同时保留可见 CTA。

## §1 标准卡片模板

### 1.1 模板选择

| 对话环节 | 标准模板 | 典型能力 |
|----------|----------|----------|
| 澄清与补充 | 澄清组件 | 补充字段、选择条件、确认输入 |
| 富媒体候选 | 富媒体候选列表组件 | 通过图片、标签、主次值帮助选择 |
| 文本候选 | 文本列表组件 | 通过标题和少量文本完成比较或选择 |
| 执行前确认 | 摘要确认组件 | 汇总对象、关键字段和动作后果 |
| 单对象展示 | 详情组件 | 展示关键信息、状态或摘要 |
| 结果反馈 | 状态结果组件 | 展示成功、失败、已受理或处理中 |

资金确认和凭证详情不是独立业务模板：前者是摘要确认的安全 profile，后者是详情组件的可回看 profile。只在体验契约明确需要时叠加。

### 1.2 澄清组件

| 模块 | 规范 |
|------|------|
| 字段构成 | 由体验契约确认的字段行、选项和结构化实体摘要组成 |
| 基础布局 | 左侧字段名，右侧输入值、选择值或占位提示 |
| 输入 | 当前原子组件不生成真实输入框；使用可点击展示行打开半屏或发送上行消息补全 |
| 选择器 | 点击后进入半浮层或半屏完成选择；卡片内可展示已选结果 |
| 选项 | 可在当前卡片内直接选择，选中态必须清晰 |
| 提交 | 主按钮提交表单，并触发字段校验 |
| 错误提示 | 原子组件可使用 `my.showToast` 做轻提示；涉及持久状态、失败原因或下一步引导时仍优先使用卡片内 notice |
| 来源展示 | 底部按业务需要展示服务来源或小程序名称 |

### 1.3 输入与选择状态

| 类型 | 状态 | 展示规则 |
|------|------|----------|
| 单行输入 | 默认、输入中、已输入、不可编辑 | 默认展示占位文案；已输入展示值；不可编辑使用弱文本色 |
| 多行输入 | 默认、输入中、已输入、不可编辑 | 长文本最多展示 2 行，更多内容用半屏承接 |
| 单选 | 选中、未选中、不可选择 | 主标题最多 1 行，辅助信息或标签最多 1 行，补充说明最多 2 行 |
| 多选 | 选中、未选中、选中不可选、未选中不可选 | 必须保留明确的可选/不可选视觉差异 |

### 1.4 结构化实体 profile

地址、联系人、身份或其他结构化对象仅在接口事实和体验契约要求时作为澄清组件的字段 profile 使用，不单独构成标准模板：

- 直接展示 2-4 个完成判断所需字段，敏感原值遵循 `SAFETY_POLICY.md` 分层或脱敏。
- 缺失或格式错误时展示字段状态，不自行推断默认值。
- 复杂编辑和选择进入半屏、原页面或上行消息，不在卡片内复刻完整表单。

### 1.5 富媒体候选列表组件

| 模块 | 是否必需 | 规范 |
|------|----------|------|
| 列表标题 | 可选 | 仅在标题有助于理解候选集合时展示 |
| 候选图片 | 可选 | 支持 1 张有事实来源的清晰图片 |
| 主标题 | 必需 | 候选项核心名称，最多 2 行 |
| 辅助信息 | 可选 | 帮助理解候选项；每类最多 1 行 |
| 标签区 | 可选 | 最多 1 行；默认灰色；最多 1 个彩色标签 |
| 标签颜色 | 可选 | 蓝色用于信息总结或强化特征，橙色仅用于有事实依据的提醒或强调 |
| 主次值区 | 可选 | 展示金额、距离、时间、数量或其他有依据的关键值，不默认生成价格 |
| 行动点 | 可选 | 仅在源交互映射明确存在独立行动控件，或安全承接契约设置 `ctaRequired=true` 时展示，文案最多 4 个字；存在 API 或出口本身不是生成依据 |

点击热区：
- 标题区：默认不可点击；只有体验契约定义集合级出口时才增加动作。
- 候选区：是否可点击及点击范围按源交互映射决定；源页面整项点击时沿用整项点击，再绑定体验契约中的出口。
- 主行动点：仅在源页面存在对应独立控件、安全承接契约要求 CTA，或允许差异有明确依据时展示，再按体验契约调用接口、发送上行消息或打开承接页。

### 1.6 摘要确认组件

| 模块 | 是否必需 | 规范 |
|------|----------|------|
| 对象图片 | 可选 | 仅在有可靠图片且有助于确认目标对象时展示，最多 1 张 |
| 对象标识 | 可选 | 展示来源、类型或其他短标识，最长 1 行 |
| 对象名称 | 必需 | 待确认对象的核心名称，最多 2 行 |
| 描述信息 | 可选 | 展示配置、范围或其他确认所需信息 |
| 主次值 | 可选 | 展示金额、数量、时间、距离或状态等关键值 |
| 摘要信息区 | 必需 | 分行展示会影响用户决定的字段和动作后果 |
| 核心操作按钮 | 必需 | 默认文案为确认；实际文案和动作由体验契约决定 |
| 辅助功能入口 | 可选 | 需要调整或重新选择时展示 |

数量等可变字段只有体验契约明确允许本地调整时才提供控件；删除、归零和其他状态变更遵循 `SAFETY_POLICY.md`。

#### 资金确认 profile

| 模块 | 是否必需 | 规范 |
|------|----------|------|
| 字段标题 | 必需 | 准确说明核心金额含义 |
| 核心金额 | 必需 | 展示待确认金额 |
| 辅助信息 | 可选 | 可罗列多行信息，也可点击跳转 |
| 核心操作按钮 | 必需 | 文案必须描述用户将进入的承接流程，不得暗示 Agent 已完成资金动作 |
| 相对方信息 | 条件 | 相对方会影响用户判断时展示名称和摘要 |

资金流转、支付、充值、转账、退款等动作必须服从 `SAFETY_POLICY.md`、体验契约和 JSAPI 边界。R4 资金动作不得由模板自动执行，但允许展示用户点击触发的付款/资金承接入口。

### 1.7 凭证详情 profile

| 模块 | 是否必需 | 规范 |
|------|----------|------|
| 凭证图片 | 可选 | 仅在存在可验证核心图片时展示，缺失时隐藏 |
| 来源 LOGO | 可选 | 记录明确属于该来源时展示，不能冒充其他主体 |
| 主标题 | 必需 | 记录核心标题，最多 2 行 |
| 辅助信息 | 可选 | 帮助用户理解记录，不承载未声明的动态字段 |

多条凭证组合展示时可使用横向滚动，但仍不得依赖纵向滚动。

## §2 通用设计规范

### 2.1 容器框架

| 规范项 | 规则 |
|--------|------|
| 唤起方式 | 用户通过对话唤起服务卡片 |
| 容器展示 | 容器固定展示小程序 LOGO 和名称 |
| 展开能力 | 容器支持展开按钮，点击后拉起九分屏容器展示小程序 |
| 内容区域高度 | 内容容器最大高度不超过 750px |
| 页面边距 | 容器内页面布局不要再额外设置左右边距 |
| 底部信息 | 底部保留小程序名称和展开入口 |

### 2.2 操作区

本节只适用于源交互映射明确存在独立操作控件，或安全承接契约设置 `ctaRequired=true` 的场景。整项点击、局部图标、步进器、选项、Tab、开关等交互沿用对应形态，不因业务动作存在而自动增加按钮区。

| 规范项 | 规则 |
|--------|------|
| 核心操作数量 | 建议最多不超过 3 个；不把全部源码动作无差别平铺 |
| 主次区分 | 总体用户动线的主要下一动作为主操作；其他相关动作按需作为次操作 |
| 单主按钮 | 适合确认、继续或进入承接流程等明确下一步操作 |
| 组合按钮 | 左侧为次按钮，右侧为主按钮 |

### 2.3 栅格与间距

| 场景 | 间距规则 |
|------|----------|
| 卡内栅格 | 卡片内容区域四周边距 16px |
| 信息栅格（行） | 信息模块之间纵向间距 12px |
| 信息栅格（列） | 同一信息组按层级使用 2px、4px、6px、8px、12px |
| 模块内间距 | 以 4px 为基础单位，按 4/8/12/16 递进 |

### 2.4 圆角

| 对象 | 圆角 |
|------|------|
| 卡容器 | 20px |
| 模块容器 | 按层级和尺寸使用 4px、8px、12px、16px |
| 图片 | 跟随模块层级，常用 8px 或 12px |
| 标签 | 4px 或胶囊形 |

### 2.5 字符大小

| 属性 | 字号 | 使用场景 | 字重 | 行高 |
|------|------|----------|------|------|
| 标题 | 15px | 卡片标题、模块标题、重要信息 | Regular / Medium | 1.4 |
| 辅助 | 13px | 副文案、描述信息 | Regular / Medium | 1.4 |
| 补充 | 11px | 标签、补充信息 | Regular / Medium | 1.4 |
| 数字 | 28px / 21px / 17px / 15px | 金额、计数、编号等需要强调的数字展示 | Medium | 按视觉需要 |

### 2.6 字符颜色

| 色值 | 用途 |
|------|------|
| `#000000` | 标题、重要描述、选项按钮等强信息 |
| `#666C81` | 主体辅助信息、标题辅助信息 |
| `#999DAB` | 补充信息、展开行动点 |
| `#BFC2CA` | 弱补充信息、低强调文本 |
| `#1677FF` | 信息高亮、按钮选中态 |
| `#4B6B99` | 文字链接 |
| `#FF3141` | 警示信息 |

按钮辅助色：
- 次级按钮文案：`#0B2B80`
- 次级按钮未选文案：`rgba(11, 43, 128, 0.3)`
- 次级按钮底色：`rgba(22, 119, 255, 0.12)`
- 置灰按钮底色、分割线：`rgba(0, 0, 0, 0.04)`

### 2.7 按钮样式

| 类型 | 规范 |
|------|------|
| 主按钮 | 蓝色渐变，核心色值 `#0F2E7F` 和 `#3363E3`，文字 `#FFFFFF` |
| 次按钮 | 浅蓝底色和深蓝文案 |
| 失效按钮 | 低对比灰底和弱文本色 |
| 文字按钮 | 用于展开更多等轻量操作，文字与箭头约 4px 间距 |
| 按钮组合 | 左次右主，保持清晰主次关系 |

## §3 溢出与降级

| 场景 | 策略 |
|------|------|
| 候选项或对象标题过长 | 主标题最多 2 行，超出截断 |
| 辅助信息过多 | 每类最多 1 行；非关键信息移入半屏或关联页 |
| 标签过多 | 最多 1 行；最多 1 个彩色标签 |
| 列表过长 | 每页最多展示 3 个高价值项，超过 3 个必须使用卡片内上一页/下一页分页；半屏或关联页仅承接详情或完整原页面流程 |
| 卡片高度接近 750px | 裁剪字段，保留主操作，更多内容进入半屏或原页面 |
| 图片缺失 | 隐藏图片区或使用低强调占位，不展示破图 |
| 字段缺失 | 隐藏该行，不展示无意义占位符 |

## §4 交互结构映射

| 用户目标 | 推荐模板或 profile | 核心展示 | 核心操作 |
|----------|-------------------|----------|----------|
| 补充缺失信息 | 澄清组件 | 字段、当前值、占位和选项 | 补充或确认 |
| 比较图文候选 | 富媒体候选列表 | 图片、标题、标签、主次值 | 查看或选择 |
| 比较文本候选 | 文本列表 | 标题、补充信息、状态和值 | 查看或选择 |
| 执行前核对 | 摘要确认 | 目标对象、关键字段和动作后果 | 确认或调整 |
| 核对最终资金/身份动作 | 摘要确认 + 资金确认 profile | 金额、相对方和后果摘要 | 打开用户承接流程 |
| 查看单对象或凭证 | 详情；按需叠加凭证详情 profile | 核心结论和关键字段 | 查看详情或无操作 |

结论：常见高频链路使用标准模板；模板只提供容器、信息层级和视觉 token，不把业务动作自动实现为按钮。不能套入标准模板的个性化场景，按通用设计规范和源交互映射实现。
