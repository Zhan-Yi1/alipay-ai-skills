# 子 Agent 隔离协议

## 1. 适用范围

本协议用于源码规模较大、业务能力分散或鉴权链路复杂的支付宝小程序项目。满足以下任一条件时启用：

- 页面数量超过约 20 个；
- 存在多个 `subPackages`；
- 目标页面或请求封装文件较大，无法在一个上下文中稳定完成局部追踪；
- 目标能力分布在多个业务域，且存在共享鉴权或状态依赖。

小项目直接由主 Agent 分析源码，不启动本协议定义的分析子 Agent。

本协议只拆分源码分析。Skill 的接口、组件、文档和宿主配置由主 Agent 统一生成，不为每个 Skill 启动实现子 Agent。

## 2. 角色与职责

| 角色 | 数量 | 主要职责 | 是否写业务代码 |
|------|------|----------|----------------|
| 主 Agent | 1 | 建立索引、划分分析场景组、调度分析、汇总事实、设计并生成全部 Skill | 是 |
| 鉴权提取 Agent | 1 | 提取登录、token、签名、请求封装和 storage 事实 | 否 |
| 鉴权核对 Agent | 1 | 按来源位置核对鉴权事实 | 否 |
| 场景分析 Agent | 每个分析场景组 1 个 | 从组内各真实入口追踪实际实现、参数、结果、可见动作和跨能力关系 | 否 |

除主 Agent 外，任何子 Agent 不得继续派生子 Agent，不得递归扫描整个项目。

## 3. 共享产物

大项目的分析结果统一写入源项目的 `.alipay-ai-skills/`：

```text
.alipay-ai-skills/
  capability-index.json
  auth-spec.md
  auth-spec.snippets.txt
  interface-spec.<scene>.md
```

这些文件是 Agent 之间的交接面。子 Agent 回传消息只包含状态、产物路径和不超过 20 行的摘要，不回传源码原文或完整请求响应。

小项目不启动分析子 Agent，但主 Agent 仍须在同一目录按分析场景组生成同格式的 `interface-spec.<scene>.md`。项目规模只决定分析者，不改变 Gate C 的产物契约。

## 4. 能力索引

能力索引由主 Agent 建立，目标是定位源码坐标，不解释接口语义。

### 4.1 允许读取的内容

- `app.json` 的 `pages`、`subPackages` 和 `tabBar`；
- 目标页面的 `.json` 标题和组件声明；
- 目标页面 `.axml` 的可见文案、输入控件和 `on*` 事件名；
- 页面 JS 的函数名、handler 名和行号；
- 目标能力关键词命中的请求调用和 JSAPI 行号。

优先使用 `rg` 或等价的行号搜索，不读取业务函数体。

### 4.2 文件格式

```json
{
  "projectScale": {
    "pageCount": 42,
    "subPackageCount": 8,
    "large": true
  },
  "capabilities": [
    {
      "name": "搜索商品",
      "subPackage": "goods",
      "page": "pages/search/index",
      "entryHandler": {
        "name": "onSearchConfirm",
        "line": 88
      },
      "uiHints": ["搜索商品", "关键词"]
    }
  ]
}
```

索引存在时直接复用，不重新生成。主 Agent 根据源界面、连续用户流程、共享关键上下文和接口上下游关系把相关索引项归入分析场景组，再把组内索引项一并交给场景分析 Agent。分析场景组只限定源码读取范围，不预设最终 Skill 归属。同一源界面上的可见动作只要对应用户总体范围内任一目标能力，就随该界面进入分析；动作连接其他功能域时记录跨能力关系。仅因代码位于同一请求文件不合并无关能力，范围过大的流程可按独立源界面拆分。

场景分析 Agent 不得跳过索引，从 `app.json` 重新遍历无关分包。

## 5. 鉴权提取 Agent

### 5.1 输入与读取范围

输入为项目路径、目标能力范围和索引路径。允许读取：

- `app.js`；
- 主包请求封装，如 `utils/request.js`、`http.js` 或 `api.js`；
- 登录、授权码、token 换取和签名文件；
- 这些文件直接引用的一层鉴权依赖；
- 主包 storage 初始化代码。

不得读取商品、订单等业务页面的完整实现。

### 5.2 `auth-spec.md`

至少记录以下事实，每条事实附 `文件:行号`：

- 请求封装是否统一，以及请求入口；
- host、环境和 URL 拼接规则；
- 通用 header、query、body 参数；
- token、session、用户标识和设备标识的来源，以及完整有效性条件、过期安全窗口和涉及的全部 storage key；
- 支付宝授权码或登录接口的调用链、参数名和响应取值路径，并区分独立登录能力与受保护业务请求；
- 签名、加密、指纹或其他动态字段；
- token 失效、登录失败和匿名降级行为；
- storage key、初始值和初始化条件；
- 响应信封和错误字段。

场景分析 Agent 通过 `authRefs` 引用这些事实，并只在场景规格中补充具体 API 的鉴权差异。

### 5.3 `auth-spec.snippets.txt`

需要精确迁移的签名函数、加密函数、token 注入段和相关完整小文件按原文保存，并为每段标注文件路径、行号和 anchor。禁止将算法改写为概括步骤或凭印象重写。

鉴权提取 Agent 的回传消息仅说明两份产物是否完成，并给出不超过 20 行的事实摘要。

## 6. 鉴权核对 Agent

鉴权核对 Agent 的输入只有 `auth-spec.md`、`auth-spec.snippets.txt` 和其中引用的来源位置。

它逐条回到指定行核对，输出以下两种结果之一：

```text
PASS
```

或：

```json
{
  "status": "DIFF",
  "items": [
    {
      "field": "tokenResponsePath",
      "specValue": "data.token",
      "sourceValue": "data.data.token",
      "source": "src/auth.js:73"
    }
  ]
}
```

核对 Agent 不修改业务代码、不评价实现风格，也不重新扫描未被引用的鉴权文件。

## 7. 场景分析 Agent

### 7.1 输入

每个场景分析 Agent 接收：

- 用户确认的总体目标能力清单；
- 分析场景名称、源界面边界和组内能力清单；
- `capability-index.json` 中组内各能力的页面、分包、handler 和行号；
- `auth-spec.md`；
- 存在组件可见网络动作时的 `ANALYSIS_PATTERNS.md §2.2、§4` 路径；
- 存在状态变更动作时的 `SAFETY_POLICY.md §2` 路径；命中不可逆候选时必须同时读取 §2.2；
- 需要时的其他参考文档路径。

### 7.2 读取边界

场景分析 Agent 必须从组内每个真实入口开始，按源码实际存在的执行链局部读取：

```text
AXML 事件
  -> 页面 handler
  -> data / onLoad / onShow / 事件参数
  -> storage / JSAPI / globalData
  -> 请求封装 -> 实际 URL、method、参数和响应（存在网络请求时）
  -> 本地逻辑 -> 输入、输出和状态变化（存在本地处理时）
  -> 页面跳转 -> 目标路径、query 和上下文要求（需要页面承接时）
```

约束如下：

- 从索引坐标对应的文件和代码段开始；
- 一般业务依赖只沿实际执行链局部追踪；组件可见动作的直接执行链递归追到请求、session、实际调用的 JSAPI、storage、模块状态、刷新和失败分支；
- 累计打开业务源码文件通常不超过约 8 个，`auth-spec.md` 和本协议列出的参考文档不计入该数量；
- 只分析当前场景组涉及的页面、实现链路和接口关系；当前源界面中映射到总体目标能力的可见动作属于该场景读取范围；
- 动态字段必须追到真实赋值来源；
- 失败、缺省和分支参数按源码记录，不自行添加默认值；
- 无法确认时返回 `need_confirm`，不得扩大读取范围。

### 7.3 输出 `interface-spec.<scene>.md`

一份场景规格覆盖组内全部能力、执行链和跨能力关系，以表格和短字段为主，共享事实只记录一次。按以下顺序交接：

- **场景入口**：总体目标范围、当前源界面、组内能力和真实入口。
- **共享事实**：共同使用的源码文件、请求入口、`authRefs`、storage、页面上下文和刷新机制。项目级鉴权通过 `authRefs` 引用；各 API 只补自身差异。
- **API 证据**：每个执行链分别记录真实入口与来源行号、method、URL path、本地逻辑或源码页面跳转、输入及真实参数来源、实际消费或下游需要的输出路径、JSAPI 和特有错误分支。
- **可见动作**：按“点击区域与事件关系、校验或确认、参数来源、动作后果、安全等级、完整源码执行链、已有 session 路径、恢复路径、刷新与失败恢复”记录总体目标范围内的动作；Gate B.5 默认排除的不可逆动作只记录判断理由和可靠原页面，不延续内部标记，也不列为候选接口。
- **接口关系**：按“生产链、判别值、源码分支、消费链、跨能力传递字段、状态新鲜度”记录列表/搜索到详情、查询到修改等关系。上游结果存在判别字段时，逐个记录源码可达值对应的 handler 分支、下游请求或跳转及实际传递字段。
- **未确认事实**：记录候选差异和最小待核对源码路径；无法通过静态源码确认时返回 `need_confirm`。

规格使用源字段和候选接口标识交接事实，供 Gate D 完成后续设计。优先使用表格和短字段，通常控制在约 60-120 行；源码歧义、安全风险或下游契约需要更多证据时补充相关内容。

场景分析 Agent 只写接口规格，不生成 `skills/`、`mcp.json`、API 实现、组件或 `SKILL.md`。

## 8. 主 Agent 的生成边界

主 Agent 读取索引、鉴权产物和接口规格后，统一完成：

- 源交互复核、接口与 schema 设计、Skill 划分和 `design.md`；`design.md` 单列默认排除的不可逆能力、原因、源码位置和可靠原页面；
- 全部 Skill 的 API、组件、工具模块和 `SKILL.md`；
- 所有 `mcp.json`；
- 基于最终 Skill 路由生成或增量更新全局 instruction 文件（默认 `AGENTS.md`）；
- `app.json` 的 Skill 与分包注册；
- 公共鉴权、请求和 Result 逻辑的统一实现。

主 Agent 不得重新执行全项目源码扫描。生成过程中如需源码证据，只能按索引和接口规格中的文件位置进行局部读取。

不为每个 Skill 启动实现 Agent。统一生成可以保证公共工具、Result 契约、鉴权迁移、组件模式和宿主注册的一致性，并避免跨 Agent 合并业务代码。

## 9. 回传与异常协议

所有分析 Agent 的消息必须满足：

- 只报告状态、产物路径、证据摘要和阻断原因；
- 不回传源码原文、完整请求响应或敏感值；
- 不输出与任务无关的搜索结果；
- 不在消息中重复已经落盘的长文档。

统一状态：

| 状态 | 含义 |
|------|------|
| `success` | 目标分析完成，产物已落盘 |
| `need_confirm` | 依赖超出读取边界或存在无法判定的分支 |
| `blocked` | 缺少源码、插件或必要运行条件 |
| `error` | 工具或文件读取失败 |

`need_confirm` 必须同时返回已读取文件列表、未确认事实和最小需要补充的路径，不得自行扩大上下文。

## 10. 并发限制

- 鉴权提取和鉴权核对各只运行一个；
- 场景分析 Agent 可按场景组并行，调度器同时最多运行三个；
- Skill 生成只由主 Agent 完成。

所有 Agent 使用共享文件系统交接，消息只传路径和摘要，避免把大段产物复制到主 Agent 上下文。
