# 标准卡片样式迁移

## §1 概述

样式迁移不是复刻原页面，而是把原页面的业务视觉线索映射到新规范卡片模板：澄清、富媒体候选列表、文本列表、摘要确认、详情、状态结果；按需叠加资金确认或凭证详情 profile。

迁移只负责视觉与交互形态适配。按钮、半屏入口、关联页和上行消息必须来自体验契约。

必须先读取对应源页面及其引用组件，完成展示结构、字段顺序、交互骨架和视觉语义提取，再选择视觉承载型并应用支付宝现有视觉规范；不得先选模板再反推源界面。

### §1.1 规范优先级（硬规则）

样式迁移必须先满足标准规范，再吸收与标准兼容的源页面视觉线索。标准规范是约束，源样式只是业务与视觉语义证据，不是目标组件的样式基准。

按以下职责和优先级执行：

1. `ACSS_SPEC.md`：决定 ACSS 可用语法、标准色值、字号、间距、圆角、按钮等硬性 token。
2. `ATOMIC_COMPONENT_DESIGN.md` 与 `COMPONENT_TEMPLATES.md`：决定组件层级、信息密度、操作区和标准模板结构。
3. 本文档：决定如何从源页面提取证据并映射到上述标准。
4. 源页面 AXML/JS/ACSS：仅提供业务结构、字段顺序、交互骨架、事实图片比例和视觉语义参考。

发生冲突时必须按上列优先级裁决：

- 源页面的品牌色、按钮色、字号、间距、圆角、阴影或布局与标准 token 冲突时，一律使用标准 token。
- 主按钮必须使用标准蓝色渐变，次按钮必须使用标准浅蓝底色与深蓝文案；不得用源品牌主色替换。
- 标准 token 的数值和单位必须原样使用，例如 `20px`、`16px`、`15px`；不得换算为 `rpx` 或近似值。非 token 尺寸才可按组件需要使用其他合法单位。
- 源品牌色仅可用于标准规范未限定的品牌标识、具有业务依据的状态/标签或轻量强调，不得覆盖卡容器、正文层级和主次按钮规范。
- 只有用户明确要求保留某项品牌表达、且标准规范未对该位置作硬性规定时，才可保留；必须在 Gate D `design.md` 和组件 ACSS 顶部注释中记录来源、理由、具体值及影响范围。未记录即视为不允许。

## §2 八步执行清单

### Step 1 — 定位源页面

- 根据目标原子能力定位对应页面；涉及列表、详情或结果状态时，选择最能代表该能力展示与操作方式的页面。
- 定位页面 AXML、JS、ACSS，以及页面引用的业务组件和相关公共样式。

### Step 2 — 读取源实现

- 读取 AXML，理解页面与列表组织方式、信息分组、字段绑定和可见节点。
- 读取 JS，理解点击处理、状态变化、校验/确认、请求/跳转、刷新和失败反馈。
- 读取 ACSS，定位目标能力相关样式块；忽略 `page {}`、全局背景和整页滚动布局等页面级样式。
- 读取引用业务组件的 AXML、JS、ACSS；交互由引用组件实现时不得只分析页面入口。
- 此阶段不得选择标准模板或先写目标组件结构。

### Step 3 — 提取展示结构与字段顺序

按源 AXML 和业务组件记录：
- 页面、模块、列表项和操作区的层次关系。
- 标题、图片、关键值、描述、标签、状态和操作的展示顺序。
- 与目标能力相关的字段绑定、条件渲染、空态、禁用态和售罄态。
- 图片比例、标签语义、按钮主次关系和信息分组。

### Step 4 — 提取源交互骨架

按源 AXML、JS 和业务组件记录：
- 整项点击、局部按钮、图标、Tab、筛选项、选择项和数量步进器等交互节点。
- `onTap` / `catchTap` 等事件、父子事件关系和冒泡阻断。
- 操作顺序，以及点击后的选中、禁用、提交中、成功和失败反馈。
- 输入、选择、弹窗、滚动、轮播和页面跳转等后续需要适配的交互。

### Step 5 — 提取视觉语义

从源样式中提取：
- 品牌色、强调色、警示色。
- 字号层级和数字字号。
- 信息组间距、卡内边距、按钮高度。
- 圆角、图片比例、阴影。
- 标签颜色语义：AI 总结/强化特征、营销、普通标签。

逐条评估：
- 可迁移：事实图片比例、字段顺序、标题/关键值层级、标签语义、按钮主次关系；按钮只迁移主次关系，不迁移源按钮色值和外观。
- 有条件迁移：品牌色仅可用于 §1.1 允许的品牌标识、状态/标签或轻量强调。
- 需改写：与标准 token 冲突的色彩、字号、间距、圆角和阴影，以及页面级边距、纵向滚动、弹窗、输入框、选择器、复杂定位。
- 不迁移：ACSS 禁用属性、页面背景、营销装饰、与目标能力无关的样式。

### Step 6 — 选择视觉承载型

完成 Step 1-5 后，再根据展示结构、字段类型和交互骨架选择：澄清、富媒体候选列表、文本列表、摘要确认、详情或状态结果；资金确认和凭证详情仅在体验契约明确需要时作为 profile 叠加。

### Step 7 — 应用支付宝现有视觉规范

先按 `ACSS_SPEC.md`、`ATOMIC_COMPONENT_DESIGN.md` 和 `COMPONENT_TEMPLATES.md` 建立标准组件，再加入不冲突的源页面视觉线索。下表中的数值、色值和单位必须精确使用，不得被源主题替换或近似换算。

| 源属性 | 标准卡片替代 |
|--------|--------------|
| 自定义字号 | 标题 15px、辅助 13px、补充 11px；需强调的金额、计数或编号用 28px/21px/17px/15px |
| 自定义间距 | 卡内 16px；模块间 12px；内部按 2/4/6/8/12px 层级 |
| 自定义色彩 | 转换为具体色值；文字使用 `#000000`、`#666C81`、`#999DAB`、`#BFC2CA` |
| 自定义圆角 | 卡容器 20px；模块容器按 4/8/12/16px |
| 主按钮 | 蓝色渐变 `#0F2E7F` → `#3363E3`，白字 |
| 次按钮 | `rgba(22, 119, 255, 0.12)` 底色 + `#0B2B80` 文案 |
| position: fixed/sticky | 去除，改为正常流 |
| 纵向 scroll | 去除，用字段裁剪 + 半屏/关联页承接 |
| 输入框/picker | 改为可点击字段行、选项、半屏或上行消息 |

按映射关系重写 ACSS：
- 直接生成目标新规范模板的类名和结构。
- 标准 token 的数值和单位必须逐项核对；不得将 `px` 改写为 `rpx`，不得用近似字号、间距或圆角替代。
- 使用具体色值，不依赖 `app.acss`，不定义 `--*` 变量，不使用 `var()`。
- 使用 flex 布局替代 float、复杂 position、grid。
- 类名使用模板前缀，如 `.clarify-*`、`.rich-*`、`.generic-list-*`、`.confirm-*`。
- 根节点不写固定高度；内容区最大高度不得超过 750px，超出必须裁剪。
- 卡容器圆角使用 20px；内部模块按层级使用 4/8/12/16px。

### Step 8 — 差异审计

| 差异点 | 处理策略 |
|--------|----------|
| 页面有纵向 scroll-view | 卡片展示核心字段，更多内容用半屏或 relatedPage |
| 页面有横向 scroll-view | 仅保留 `<scroll-view scroll-x>`，禁止 `scroll-y` |
| 页面有横向 swiper | 可保留横向 `swiper` / `swiper-item` 和 `onChange`；禁用纵向、自动高度、禁用触摸、动画结束和过渡事件 |
| 页面有输入框 | 澄清组件字段行 + 半屏/上行消息 |
| 页面有 picker | 澄清组件选择行 + 半屏/卡片内选项 |
| 页面有弹窗 | 改为半屏或上行消息确认 |
| 页面有 tab 切换 | 简化为选项组或按钮组 |
| 页面有图片轮播 | 取首图 + 图片计数 |
| 页面有长列表 | 富媒体候选列表和文本列表每页最多展示 3 项；超过 3 项时使用卡片内上一页/下一页分页，半屏或关联页仅承接详情或完整原页面流程 |
| 页面有多个操作按钮 | 保留主操作和最多 2 个次操作 |
| 页面有完整原页面流程 | 卡片只保留入口，使用 relatedPage 或半屏承接 |
| 页面操作无体验契约依据 | 不迁移该操作 |
| 源品牌色用于主/次按钮 | 改为标准蓝色主按钮与标准浅蓝次按钮；品牌色只在允许的语义位置使用 |
| 源字号、间距或圆角接近标准值 | 仍替换为标准 token 的精确数值和单位，不做近似保留 |

完成迁移后必须逐项确认：

- 卡容器、字号、间距、文字色和圆角均来自标准 token，且数值与单位完全一致。
- 主按钮使用 `#0F2E7F` → `#3363E3` 蓝色渐变；次按钮使用 `rgba(22, 119, 255, 0.12)` 底色和 `#0B2B80` 文案。
- 源品牌色没有覆盖标准正文层级、卡容器和主次按钮。
- 所有允许保留的品牌表达均已在 Gate D `design.md` 和组件 ACSS 顶部注释中记录。

组件 `.acss` 顶部必须写注释说明样式来源和差异：

```css
/* 样式参考：pages/example/list.acss
 * 标准模板：富媒体候选列表组件
 * 字段映射：cover/name/mainValue/tags -> imageUrl/title/primaryValueText/tags
 * 标准色：主按钮渐变 #0F2E7F -> #3363E3；文字 #000000 / #666C81 / #999DAB / #BFC2CA
 * 源语义色：app.json tabBar.selectedColor #1677ff，仅用于标准允许的选中/轻强调位置
 * 源样式差异：
 *   - 源双列宫格改为标准富媒体候选纵向列表
 *   - 源输入框改为可点击字段行和半屏承接
 *   - 源页面圆角不保留，卡容器使用 20px
 */
```

写不出这段注释时，说明迁移证据不足，必须回到源码样式和体验契约补齐。

```markdown
| 源选择器 | 源属性 | 标准模板 | 目标选择器 | 目标属性 | 变更说明 |
|----------|--------|----------|------------|----------|----------|
| .source-card | border-radius: 12px | 富媒体候选列表 | .rich-card | border-radius: 20px | 使用新卡容器圆角 |

| .source-value | color: #ff5000 | 富媒体候选列表 | .rich-primary-value | color: #000000 | 按关键值层级强调 |

```

## §4 视觉 Token 提取模板

```markdown
## 源页面视觉 Token

**色彩**
- 源品牌主色: #{hex} → 仅用于标准允许的品牌标识、选中、状态/标签或轻强调；不得用于主/次按钮
- 主按钮: 无条件使用 #0F2E7F → #3363E3 蓝色渐变
- 次按钮: 无条件使用 rgba(22, 119, 255, 0.12) 底色 + #0B2B80 文案
- 辅色: #{hex} → 映射为普通标签或丢弃
- 警示色: #{hex} → 映射为 #FF3141
- 文字色: #{hex} → #000000 / #666C81 / #999DAB / #BFC2CA

**字号**
- 标题: {n}px → 15px
- 辅助: {n}px → 13px
- 补充/标签: {n}px → 11px
- 强调数字: {n}px → 28px / 21px / 17px / 15px

**间距**
- 卡内边距: {n}px → 16px
- 模块间距: {n}px → 12px
- 组内间距: {n}px → 2px / 4px / 6px / 8px / 12px

**圆角**
- 卡容器: 20px
- 模块容器: 4px / 8px / 12px / 16px

**图片**
- 核心对象图: 固定尺寸 + aspectFill
- 头像/LOGO: 固定尺寸，避免加载后撑高

**特殊**
- 标准 token: 数值和 `px` 单位原样使用，不换算为 `rpx`，不使用近似值
- 阴影: 简化为轻阴影或去除
- 渐变: 仅保留简单 linear-gradient
```
